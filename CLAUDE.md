# Jiggl — project notes

Work-management + time-tracking SaaS with a PM layer (offers → orders → epics, sold vs consumed budgets). Inspired by the leading SaaS products in both categories, but **never name closed-source products** (the user asked to remove such references) in code, comments, docs or seed data. UI/UX first, one design system for everything: toolbars and filters use chips, lozenges and detail panels, never plain bordered form fields.

- **Stack**: Next.js 16 App Router (Turbopack), React 19, TypeScript, Tailwind v4, Zustand, @dnd-kit, date-fns, lucide-react. Backend: Next route handlers + Prisma 6 + Postgres, session cookie (JWT via `jose`, scrypt passwords), multi-workspace.
- **Data flow**: the Zustand store (`src/lib/store.ts`) is the client cache. On load `AppShell` calls `GET /api/bootstrap` and `applyBootstrap`; `src/lib/sync.ts` then watches the store, diffs collections by object identity and pushes batches to `POST /api/sync` (write-through, last write wins). Store reducers must keep untouched entities referentially equal, or the sync re-uploads everything. Only the `ui` slice is persisted in localStorage.
- **Server**: `src/server/workspace.ts` maps collections ↔ Prisma models generically through the DMMF (`toRow`/`fromRow`); every workspace-scoped model has the composite key `(workspaceId, id)` and `syncedAt` bookkeeping. Demo data comes from `src/lib/seed.ts` (`seedDemo`), where the registering account replaces the seed user `u_alex`. Pages are protected by `src/proxy.ts`; API routes call `requireSession()`.
- **Database**: Postgres (local `docker-compose.yml`, or any instance reachable through `DATABASE_URL`). Credentials in `.env` (git-ignored; template in `.env.example`). This repository is public: never commit hostnames, IPs, paths or names of private infrastructure; keep those in the private memory notes. Schema changes: edit `prisma/schema.prisma`, create a migration with `npx prisma migrate diff --from-url "$DATABASE_URL" --to-schema-datamodel prisma/schema.prisma --script > prisma/migrations/<stamp>_<name>/migration.sql` (the database must be at the last migration; `--from-migrations` would need a shadow database), then `npx prisma migrate deploy` and `npx prisma generate` (`migrate dev` needs a TTY).
- **Outgoing email**: per-workspace SMTP settings in the `WorkspaceMail` model (Settings → Outgoing email, workspace admins). The password is encrypted with AES-GCM keyed from `AUTH_SECRET` (`src/server/crypto.ts`) and never sent to the client (`hasPassword` only). `src/server/mail.ts` sends through nodemailer; the messages are built in `src/lib/mail.ts` (text and HTML from one content model). The invite and password routes send best-effort after their transaction and return `mail: { sent, error? }` (undefined when nothing is configured); the Team modals show it. `e2e/mail.spec.ts` runs a throw-away SMTP server on 127.0.0.1.
- **Members**: workspace admins deactivate or remove members from Team (`PATCH` / `DELETE /api/workspace/members`). `deactivatedAt` is server-managed: `toRow` never writes it from the sync, and login, bootstrap, sync and switch refuse deactivated members (`requireMember`, `firstActiveMembership` in `src/server/members.ts`). Deactivated members keep their history and are left out of pickers through `pickable()`; removal is allowed only when `memberUsage()` (`src/lib/team.ts`) finds nothing referring to them, and the store's `removeUser` cleans teams, rate overrides and watchers. `e2e/members.spec.ts` covers both.
- **Domain**: client > project (status prospect/active/closed, pricing fixed/tm, timeMode timesheet/allocation) > offers (lines → work items on conversion) and time entries. Rates are dated periods (`RatePeriod[]`); resolve with `src/lib/rates.ts`. Budgets in `src/lib/budget.ts`, offers helpers in `src/lib/offers.ts`.
- **Allocations**: virtual time entries (`virtual: true`) are generated on the fly by `useEffectiveEntries()` and never stored; every consumer of time entries must use that hook unless it really wants only tracked hours.
- **Design tokens** live in `src/app/globals.css` (`--ds-*` → Tailwind `ds-*`, plus `lz-*` lozenge, `chart-*` and `ds-accent-*` colours). Light and dark values are both defined there; the theme is applied as `data-theme` on `<html>` by `src/lib/theme.ts` (inline script in the root layout avoids a flash). Never hard-code hex colours in components: use token classes, or `var(--ds-…)` in inline styles / SVG `style` props (SVG presentation attributes do not accept `var()`). Entity colours (project, avatar) are data and stay hex. Custom classes are in `@layer components` so utilities can override them. Check dark mode with `THEME=dark node scripts/screenshots.mjs …` (output in `.screenshots/dark/`).
- **Routes**: pages are client components; dynamic params via `use(params)`; use the generated `PageProps<"/...">` / `LayoutProps<"/...">` helpers.
- **Zustand rule**: selectors must return stable references (no `.filter/.map/({})` inside `useStore(...)`); select the base array and `useMemo`.
- **dnd-kit**: `DndContext` renders a live-region div, so never place it inside `<table>`; wrap the table instead.
- **Responsive**: from `lg` (1024px) the sidebar is docked and collapses through the persisted `ui.sidebarCollapsed`; below it the sidebar is an overlay drawer with transient state (`toggleNavigation()` in `src/components/layout/Sidebar.tsx`) that closes on navigation, outside click and Escape. Below `md` the top-bar icons move into the "Show more" popover and the logo loses its name below `lg`. Page gutters use the `px-page` utility (16px, 32px from `md`), never `px-8`. `Tabs` moves the tabs that do not fit into a "More N" menu. Modals are full-screen below `sm`; `Popover` never exceeds the viewport and supports nested popovers. Wide tables keep their `min-w-[…]` and scroll sideways; the week calendar scrolls sideways below 640px. Below `sm` list rows turn into cards or two-line rows (For you, backlog, time entries). Gotcha: `hidden md:inline-flex` on a `Button`/`IconButton` does not hide it (the base `inline-flex` wins in the cascade): use `max-md:hidden`. Check narrow widths by loading the page in a 390px iframe.
- **Charts**: hand-written SVG in `src/components/reports/charts.tsx` (dataviz method; `grouped` for comparable series). `PROJECT_COLORS` order passes the colour-blindness validator.
- **Verification**: `npm run typecheck` (next typegen + tsc), `npm run lint`, `npm test` (Vitest unit tests in `src/**/*.test.ts`, shared builders in `src/test/fixtures.ts`; `sync.test.ts` runs in jsdom), `npm run e2e` (Playwright Test in `e2e/`: starts `next dev` on port 3210, or set `BASE=http://localhost:3000` to reuse a running server; needs the database). The exploratory Playwright scripts in `scripts/` run against a dev server (`BASE=http://localhost:3000`; on Git Bash also `MSYS_NO_PATHCONV=1` when passing routes). Each script registers a throw-away account with the demo dataset (`scripts/_session.mjs`) and deletes it at the end, so it needs the database. They use the system Chrome, no browser download.
- **CI and branch policy**: `.github/workflows/ci.yml` runs `checks` (typecheck, lint, unit tests) and `e2e` (Postgres service, production build) on pushes to `main` and on pull requests. A GitHub ruleset makes `main` PR-only with both checks required (repository admins can bypass); never push to `main` directly, open a PR.
